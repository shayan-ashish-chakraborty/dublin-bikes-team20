main_project.weather.services._fetch_nearest_weather(dt_str: str) → dict | None[source]

Find the nearest hourly weather record to a given datetime.

Queries the DB hourly table first (within ±3 hours of dt_str), then falls back to the live OpenWeatherMap forecast API if no DB row is found.

Parameters:

dt_str – Target datetime string in "YYYY-MM-DD HH:MM:SS" format (Irish local time).

Returns:

A weather row dict, or None if no match is found within ±3 hours and the API fallback also fails.

main_project.weather.services.openweather_current(lat: float, lon: float) → dict[source]

Fetch current weather conditions for a given location.

Tries the live OpenWeatherMap /data/2.5/weather API first. Falls back to the nearest row in the DB hourly table (Irish time) if the API key is missing or the request fails.

Uses:

  • _fetch_nearest_weather() — DB fallback when the live API key is absent or the request fails.

Parameters:

  • lat – Latitude of the target location.

  • lon – Longitude of the target location.

Returns:

dt, temp, feels_like, humidity, pressure, wind_speed, wind_gust, rain_1h, weather_desc.

Return type:

A dict with keys

Raises:

RuntimeError – If both the API and the DB fallback are unavailable.

main_project.weather.services.hourly_forecast_list_like_weather_page(limit: int = 24) → list[dict][source]

Return an hourly weather forecast using the same pipeline as the weather UI.

Pipeline:

  1. Query MySQL hourly table (primary).

  2. If empty, fall back to live OpenWeatherMap 3-hour forecast API (subject to a 5-minute cooldown).

  3. Filter to future-only rows.

  4. If fewer than 16 rows remain, supplement with API rows; DB rows take precedence within each 3-hour slot.

Uses:

  • hourly_forecast_rows_from_db() — primary source; queries the hourly MySQL table.

  • openweather_forecast_3h_list() — fallback and supplement source; calls the OpenWeatherMap 5-day/3-hour forecast API.

Parameters:

limit – Maximum number of rows to return. Clamped to [1, 100]. Defaults to 24.

Returns:

temp, humidity, pressure, rain_3h, pop, and a timestamp (dt or future_dt). Returns an empty list if both the DB and API are unavailable.

Return type:

A list of row dicts with keys

main_project.weather.routes.get_nearest_hourly_weather()

GET /api/weather/db/hourly/nearest — Return the hourly forecast record closest to a requested datetime.

Searches within a ±3-hour window. Tries the local DB first, then falls back to the OpenWeather forecast API.

Uses:

  • _fetch_nearest_weather() — queries the DB and falls back to the OpenWeather API if needed.

Example request:

GET /api/weather/db/hourly/nearest?dt=2026-04-09+12:00:00
Parameters:

dt – Target datetime string in "YYYY-MM-DD HH:MM:SS" format (query param, required).

Returns:

JSON weather row dict, or a 404 error if no match is found.

main_project.weather.routes.api_current_weather()

GET /api/weather/openweather/current — Fetch current weather conditions via the OpenWeatherMap API.

Uses:

  • openweather_current() — calls the OpenWeatherMap current weather endpoint and returns a normalised dict.

Example request:

GET /api/weather/openweather/current?lat=53.3498&lon=-6.2603
Parameters:

  • lat – Latitude of the target location. Defaults to Dublin (53.3498).

  • lon – Longitude of the target location. Defaults to Dublin (-6.2603).

Returns:

JSON with keys source and weather (current conditions dict).
